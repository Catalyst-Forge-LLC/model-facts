# ModelFacts Directory Specification — v0.1.0

> The labeled catalog at [modelfacts.dev/directory](https://modelfacts.dev/directory).
> Companion to [`SPEC.md`](./SPEC.md) (the per-model file format).

## Purpose

The directory is a **curated, browsable set of `MODEL_FACTS.md` labels** for well-known
models. It turns ModelFacts from a proposal into a useful comparison surface on day one:
developers and agents can skim architecture, training provenance, capabilities, and safety
side by side — including when the answer is `undisclosed`.

It is **not** a claim that every judgment field was independently measured. Until a
benchmark harness exists, capability and safety enums are **reviewed self-reports** drawn
from published cards and docs (see [Curation](#curation)).

## Scope (v0)

- **Open-weight models** (primary): labels generated from Hugging Face metadata + card,
  then human-reviewed.
- **Closed / API models** (secondary): hand-authored labels that lean on `undisclosed`
  wherever the lab has not published a fact. Their value is making non-disclosure visible
  next to open peers — not inventing numbers.

Target seed size for first publish: **≥ 24 models**.

**v0 open selection (2026-08):** Ollama library models with **≥ 250K pulls** and a
library update within ~**6 months** ([newest](https://ollama.com/search?o=newest) /
[popular](https://ollama.com/search?o=popular)). One representative size per family.

**v0 closed selection:** current frontier API flagships (not historical GPT-4o / Claude 3).

## Layout

Canonical labels live in the git repo. The static site serves a generated mirror.

```
directory/
  README.md                      # human overview + contribution notes
  <slug>/
    MODEL_FACTS.md               # canonical label (source of truth)

site/directory/
  index.html                     # listing page
  index.json                     # generated catalog (for the page + agents)
  <slug>/
    index.html                   # detail page (nutrition-label view)
    facts.json                   # frontmatter as JSON
    MODEL_FACTS.md               # copy of the canonical file (downloadable)
```

| Path | Role |
|---|---|
| `directory/<slug>/MODEL_FACTS.md` | **Canonical.** Edited by humans / PRs. Validated against the schema. |
| `site/directory/*` | **Published mirror.** Regenerated by `pnpm sync` in [`directory-tools/`](./directory-tools/). Never hand-edit. |

The Markdown body may drift from frontmatter (same rule as [`SPEC.md`](./SPEC.md)); the
directory tooling treats frontmatter as authoritative when building `facts.json` and the
detail page.

## Slugs

- Lowercase kebab-case ASCII: `[a-z0-9]+(-[a-z0-9.]+)*`
- Pattern: `{vendor}-{model-version}` where `vendor` is a short org key
  (`meta`, `openai`, `anthropic`, `google`, `qwen`, `mistral`, `deepseek`, `microsoft`,
  `cohere`, `xai`, `meta-llama` is shortened to `meta`, etc.)
- Examples:
  - `meta-llama-3.1-70b-instruct`
  - `qwen-qwen2.5-7b-instruct`
  - `openai-gpt-4o`
  - `anthropic-claude-sonnet-4`
- One slug = one model **version** (a quantized re-release is a new slug, matching the
  ModelFacts one-file-per-version convention).
- Slugs are stable once published; renames require a redirect note in the PR.

### Directory-only fields

These are **not** part of the ModelFacts schema; they describe the catalog entry:

| Field | Values | Meaning |
|---|---|---|
| `weight_access` | `open` \| `closed` | Open downloadable weights vs API-only / undisclosed weights |
| `curation` | `draft` \| `reviewed` | Generator draft vs human-reviewed judgment fields |
| `slug` | string | Directory id |
| `parameters_b` | number \| `null` | Parsed parameter count in billions for filters (`null` if undisclosed) |
| `context_tokens` | number \| `null` | Parsed context length in tokens for filters (`null` if undisclosed) |
| `href` / `facts_json` / `facts_md` | paths | Site URLs |

The listing page filters by developer, min params, min context, filter type, and weight access.
Min-param / min-context filters **exclude** models whose value is `undisclosed`.

`weight_access` is inferred at sync time:

- `closed` if `architecture.parameters` is `undisclosed` **and** there is no `weights` URL
  **and** the entry is listed in the closed seed set — or explicitly tagged in
  [`directory/manifest.json`](./directory/manifest.json).
- Otherwise `open`.

## Manifest

[`directory/manifest.json`](./directory/manifest.json) is the seed / membership list the
sync tool reads. It does **not** duplicate the full label; it points at sources and
directory metadata:

```json
{
  "manifest_version": "0.1.0",
  "models": [
    {
      "slug": "meta-llama-3.1-70b-instruct",
      "weight_access": "open",
      "curation": "reviewed",
      "source": { "type": "huggingface", "id": "meta-llama/Llama-3.1-70B-Instruct" }
    },
    {
      "slug": "openai-gpt-4o",
      "weight_access": "closed",
      "curation": "reviewed",
      "source": { "type": "hand" }
    }
  ]
}
```

| `source.type` | Meaning |
|---|---|
| `huggingface` | Label may be (re)drafted with the generator from `id` |
| `hand` | Label is maintained only by hand under `directory/<slug>/` |

## Curation

| Level | When to use |
|---|---|
| `draft` | Fresh generator output; judgment fields may still carry `# TODO: verify` intent |
| `reviewed` | A human checked capability/safety/training fields against the card or lab docs and removed invented claims |

Rules for `reviewed`:

1. Obey the Golden Rule ([`SPEC.md`](./SPEC.md)).
2. Prefer `undisclosed` over a guess — especially for closed labs' data mix, token counts,
   and parameter counts.
3. Capability and safety enums are **best-effort readings of published claims**, not
   ModelFacts-run evals. Do not imply certification.
4. Benchmarks must cite scores as published (use `notes` for shot count / variant).

Reserve the word **certified** for a future harness-backed tier. It is out of scope for v0.

## Site UX

### Listing (`/directory/`)

- One composition: brand-consistent with the landing page (violet accent, Sora + IBM Plex Mono).
- Filter chips: All / Open / Closed; optional text filter on name/developer.
- Compact rows (not cards-as-decoration): name, developer, params, context, filter type,
  weight_access, curation badge.
- Each row links to the detail page.

### Detail (`/directory/<slug>/`)

- Renders the nutrition-label view from `facts.json` (frontmatter).
- Links out to homepage / weights / raw `MODEL_FACTS.md`.
- Shows `weight_access` and `curation` badges so readers know the trust posture.

No backend. Cloudflare Pages, project root = `site`, no build step at deploy time — the
sync script is run in-repo before commit/publish.

## Tooling

[`directory-tools/`](./directory-tools/) (TypeScript ESM, pnpm):

| Command | Purpose |
|---|---|
| `pnpm sync` | Validate every `directory/*/MODEL_FACTS.md`, write `site/directory/**` |
| `pnpm seed` | For manifest entries with `source.type: huggingface` missing a file, run the generator (deterministic by default) into `directory/<slug>/` |

CI should run `pnpm sync` (or at least validate + confirm `site/directory` is up to date).

## Adding a model (contributors)

1. Pick a stable slug; add a row to `directory/manifest.json`.
2. Open-weight: `cd directory-tools && pnpm seed --slug <slug>` (or run the generator by hand
   into `directory/<slug>/MODEL_FACTS.md`).
3. Closed: copy [`examples/MODEL_FACTS.template.md`](./examples/MODEL_FACTS.template.md),
   fill only published facts, mark the rest `undisclosed`.
4. Human-review judgment fields; set `"curation": "reviewed"` when done.
5. Run `pnpm sync` from `directory-tools/`.
6. Open a PR. Reviews focus on Golden Rule violations and invented numbers.
